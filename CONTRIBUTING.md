# Contributing

This repository is a Bun workspace. Install Bun 1.3 or newer, then run:

```bash
bun install --frozen-lockfile
bun run quality
```

The CLI lives in `apps/anatomy-cli`; reusable tree logic is in
`packages/anatomy`; schemas and bundled definitions live in the other two
workspace packages. Keep changes self-contained and add or update tests with
behavior changes.

Run `bun run anatomy:check` for a fast whole-repository structure and function
export check. `bun run quality` includes this check and the source-role audit;
the pull-request workflow invokes the same quality command. After building, the
workspace-installed executable also works: `./node_modules/.bin/anatomy . --git-files`.

The root `anatomy.json` is a reviewed contract, not a snapshot regenerated by
tests. Every project file has an explicit required rule. When adding, moving or
removing files:

1. Update the corresponding node in `anatomy.json`. Keep structural policies at
   `block`; do not introduce a catch-all placeholder to silence a failure.
2. Function modules, hooks and components must export exactly one named function
   whose name matches the filename. Use `"exports": { "name": "file_stem" }`.
   Type exports do not count. Split additional functions or runtime constants
   into their own files and update imports and existing barrels.
3. For a non-function source file, record its exact runtime exports, role and
   reason in `anatomy.coverage.json`. Tests validate these declarations. Schemas
   export one same-named `*Schema` value with inferred types; barrels only contain
   relative wildcard re-exports; tests and process entrypoints expose no runtime
   API. Framework-owned modules use explicit reviewed exceptions.
4. For changes inside the CLI source directory or schemas package, update the
   matching subtree in `apps/anatomy-cli/anatomies/cli-source.anatomy.json` or
   `packages/schemas/anatomy.json` as well. Tests prevent these focused copies
   from diverging. `scan:self` and `scan:schemas` use our own contracts, while the
   Tellyn catalogue remains a separate set of example conventions.
5. Run `bun run quality`. For documentation-app changes also run
   `bun run docs:build:cloudflare` and
   `bun --cwd apps/docs scripts/check-cloudflare-build.ts`.

Git selection includes tracked files and non-ignored new files. Keep project
source and CI files visible to Git; only local state and generated output should
be ignored. Retain temporary plans, reports and demos under the ignored root
`docs/` directory, and never force-add them. Git mode rejects symlinks and
submodules, and does not inventory empty directories.

The module split keeps named package-level exports available, but internal file
paths have changed. Prefer the package barrels over old source-file deep imports.
