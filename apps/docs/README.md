# Anatomy CLI Docs

**English** | [简体中文](./README.zh-CN.md)

The documentation site lives in `apps/docs`. It uses TanStack Start, Payload CMS 4, Tailwind CSS 4, and shadcn-style components built on Base UI.

```bash
bun install
bun run docs:dev
```

The development server runs at <http://127.0.0.1:5173/>. Public documentation uses versioned local content and does not require a database. To use the Payload admin interface, copy `.env.example` to `.env`, start Postgres, and run:

```bash
bun --cwd apps/docs payload:migrate
```

The admin interface is available at `/admin`, and the API at `/api`.

## Automatic Cloudflare deployment

`anatomy.tools` uses Cloudflare Workers Static Assets. The `cloudflare` build mode prerenders the homepage and every documentation page in `src/content.ts` using Node.js. Only `.output/public` is uploaded. Language switching, themes, and animations continue to run in the browser. The Payload admin interface and API are outside the scope of this public deployment; the current Postgres adapter's server build cannot run directly in Workers.

```bash
bun run docs:build:cloudflare
bun run docs:deploy:cloudflare --dry-run
bun run docs:preview:cloudflare
```

Preview uses Wrangler's local runtime. Before uploading, the deployment command checks every prerendered HTML page to prevent accidentally publishing only the assets from a regular Node server build. Unknown paths return 404; `/docs` redirects to `/docs/installation`.

First-time setup:

1. Add `anatomy.tools` to the target Cloudflare account, complete DNS setup, and confirm that the domain is Active. `wrangler.jsonc` binds this domain to the `anatomy-tools` Worker.
2. Configure `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` as GitHub repository Actions secrets or `production` environment secrets. Follow Cloudflare's official GitHub Actions guide to create a deployment token, restricting its account and domain permissions to this project. Do not commit the token.
3. Use `anatomy-cli` 0.0.3 or later, which includes the one-shot installer. Both commands in npm `0.0.2` point to the same entry and do not support the homepage's installation instructions. The deployment workflow checks the published `anatomy` command entry before deployment. See [Publishing in the root README](../../README.md#publishing).
4. Merge the deployment configuration into `main`. `.github/workflows/deploy-docs.yml` runs checks, builds, and deploys after changes to the relevant pages, shared packages, or build configuration. Pull requests only validate the build; they neither read deployment credentials nor publish. You can also run **Deploy anatomy.tools** manually from Actions with `main` selected, for example after publishing the CLI release.

Successful static builds are retained as GitHub artifacts for seven days. Production deployment uses the files generated by the same workflow run and checks the HTTP status of the homepage and installation page afterward. Repository configuration alone does not bring the site online without Cloudflare credentials and an active domain.

For a manual local deployment, run `bunx wrangler login` from `apps/docs`, then return to the repository root to build and run `bun run docs:deploy:cloudflare`. To roll back, select an earlier deployment in the Cloudflare `anatomy-tools` Worker's deployment history, or revert the code and rerun the workflow.

References: [TanStack static prerendering](https://tanstack.com/start/latest/docs/framework/react/guide/static-prerendering), [Cloudflare Static Assets](https://developers.cloudflare.com/workers/static-assets/), [GitHub Actions deployment](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/), and [Custom Domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/).
